Design to Code

The design skills a frontend developer needs: how to read a Figma file, turn it into tokens and components, and build a small reusable component kit. Components use Tailwind and work the same in React and Next.

Read a Figma file like a developer

Switch to Dev Mode (the </> toggle, or Shift + D). Click any layer and the Inspect panel shows its size, spacing, colors and text style. Hold Alt and hover another layer to see the distance between them.

Habit: before writing code, list the components and tokens the screen uses. Build those first, then the screen is mostly assembly.

Design tokens

A token is a named design decision. You write bg-primary, not #0b7285, so a rebrand or dark mode is a change in one file. Copy the names from Figma's Variables panel.

Without Tailwind, the same idea is plain CSS variables on :root and var(--color-primary) in your styles.

Spacing and layout

Good layouts use a small set of spacing values, almost always multiples of 4: 4, 8, 12, 16, 24, 32, 48. If Figma shows 15 or 17, it is probably meant to be 16. Tailwind's scale is the same grid: p-4 is 16px, gap-6 is 24px.

  • Use gap on the parent for space between siblings. Avoid margins on children.
  • Related things sit close together, unrelated things get more space. Spacing is how a page shows grouping.
  • Use flex for a row or a column, grid for rows and columns together (card grids, page shells).

Typography

Use a fixed scale of sizes, not arbitrary numbers. Five or six steps cover a whole app.

RoleSize / line heightTailwind
Page title30 / 36, boldtext-3xl font-bold
Section title20 / 28, semiboldtext-xl font-semibold
Body16 / 24text-base
Secondary text14 / 20, muted colortext-sm text-muted
Label, caption12 / 16, mediumtext-xs font-medium
  • Hierarchy comes from size, weight and color together. Do not use more than two font families.
  • Keep paragraphs around 60 to 70 characters wide: max-w-prose.
  • Body text below 14px is hard to read. On phones keep inputs at 16px so iOS does not zoom.

Color and contrast

  • One primary color for the main action on a screen. If everything is colored, nothing stands out.
  • Neutrals do most of the work: background, surface, border, text, muted text.
  • Semantic colors carry meaning: success, warning, danger. Never rely on color alone, add an icon or text.
  • Contrast: text needs a ratio of at least 4.5:1 against its background (3:1 for large text). Check it in Chrome DevTools by clicking the color swatch.

Dark mode is the same tokens with different values, which is why components must never contain raw hex codes.

Design a component's API

A good component mirrors the Figma component: each Figma property becomes one prop with the same options. Rules that keep components reusable:

  • Variants are a fixed list ("primary" | "secondary"), not free-form class strings.
  • Extend the native element's props, so onClick, type, disabled and aria-* work for free.
  • Content goes in children. Layout around the component (margins, position) belongs to the parent.
  • Accept className as an escape hatch for one-off adjustments.

Accessibility basics

Most of accessibility is using the right HTML element. These six habits cover the majority of issues:

  • Something that does an action is a <button>. Something that goes to a URL is an <a>. Never a clickable <div>.
  • Every input has a <label> linked by htmlFor. A placeholder is not a label.
  • Every image has alt. Use alt="" for purely decorative ones.
  • Never remove the focus outline without replacing it. Test the page using only Tab, Enter and Escape.
  • Icon-only buttons need a name: <button aria-label="Close">.
  • One <h1> per page, then headings in order. Screen readers navigate by them.

Click targets should be at least 40 by 40 pixels, larger on touch screens.

Check it

  • Chrome DevTools, Lighthouse tab, Accessibility audit: catches missing labels, alt text and low contrast.
  • Unplug the mouse and complete the main task with the keyboard.
  • Add the lint plugin so mistakes fail early: npm install -D eslint-plugin-jsx-a11y (already included in the Next ESLint config).

Icons and assets

  • Icons: use one icon library, or export from Figma as SVG. Set fill="currentColor" so the icon takes the text color.
  • Photos and illustrations: export at 2x as WebP. In Next use next/image.
  • Logos: SVG, never PNG.

An icon exported from Figma as a component

Paste the exported SVG into a component, replace the fixed color with currentColor, and pass props through so size and color come from the parent.

Code Connect: link Figma components to yours

Code Connect tells Figma which code component matches each Figma component. Dev Mode then shows your real import and props, and AI agents reuse your component and do not invent a new one.

The left side of each mapping is the property name in Figma, the right side is your prop value. This is why matching names between design and code pays off.

Do not build everything yourself

Dropdowns, date pickers, comboboxes and tooltips are hard to get right. Use a library for those and write only the simple pieces by hand.

Handoff checklist

Run through this before calling a screen done.

  • Colors, spacing and radius come from tokens, with no raw values in components.
  • Spacing matches Figma at the three widths: phone, tablet, desktop.
  • Hover, focus, disabled, loading, empty and error states exist.
  • Long text, missing images and zero items do not break the layout.
  • The page works with the keyboard only, and focus is always visible.
  • Text contrast passes 4.5:1 in light and dark mode.
  • Repeated UI was extracted into components/ui, not copied.
  • You compared the browser and the Figma frame side by side at 100% zoom.
